RoCo: Role-Based LLMs Collaboration for Automatic Heuristic Design

让探索、利用、批评和整合生成可执行启发式，再用目标分数检验收益。

先看结论

RoCo 的核心是让不同角色生成、比较和融合可执行启发式，再用真实目标分数选择。多角色对话增加搜索路径；评分器决定候选去留。

4 个协作角色同一 GPT-4o-mini 后端；通过 Prompt 设定不同倾向。
5 类经典 COPACO：TSP、OP、CVRP、MKP、Offline BPP。
0.188%KGLS-RoCo 在 TSP200 的最优性差距；不是总体改善百分比。

研究动机

启发式设计依赖经验和反复试验。LLM 可以写候选程序，但单一路径可能缺乏探索，也可能无法把新颖想法转成稳定有效的代码。作者希望让不同角色承接不同搜索任务。[§1]

已有骨架

EoH 的种群搜索；ReEvo 的反思；HSEvo 的多样性；MCTS-AHD 的树式探索。这里是作者的文献定位，不代表过去完全没有分工。[§1–2]

本文新增

四角色通信、多轮交互、角色记忆和精英变异，作为 EoH 的协作模块。论文不是用多模型投票直接构造最终路线。[§3]

真正值得检查的问题：在相同求解接口和可核对预算下，这套协作机制能否产生更好的启发式？它在结构信息受限时是否更稳定？

算法流程 / 方法

  1. 标准进化：E1 产生与父代不同的思想；E2 提炼共同思想再重组；M1 改结构；M2 调参数。
  2. 精英选择：按排名衰减概率选第一项，再在其后相邻排名中选第二项。
  3. 比较与双分支：Critic 比较程序与表现；Explorer 探索新结构；Exploiter 局部修正。
  4. 融合：每轮 Integrator 生成融合候选；轮次结束再融合两条分支各自的最佳程序。
  5. 记忆与变异：从短期反馈及目标变化提炼角色反思，对两个精英进行三类变异。
  6. 选择：合并协作、融合、变异与 EoH 候选，再取表现最好的 N 项进入下一代。

实验设计

白盒 / 黑盒

白盒提供完整结构，如距离矩阵。黑盒只给抽象边属性，限制全局结构访问；仍有接口与目标评估，不是没有输入或只能得到标量反馈。[Appendix D]

基线

ACO、DeepACO、EoH、ReEvo、HSEvo、MCTS-AHD。GLS 另比较 KGLS 系列及学习方法；部分 GLS 基线引用 ReEvo 的结果。[§4.1；Table 4]

数据是合成实例

  • TSP：坐标均匀采样于单位正方形。
  • CVRP：depot 固定在 (0.5, 0.5)；完整需求与容量生成细节缺失。
  • OP：节点含 depot 均匀采样，奖励依赖距离：pi=1+j99⋅(d0imax⁡j=1nd0j)k100p_i = \frac{1 + \frac{j}{99} \cdot \left( \frac{d_{0i}}{\max_{j=1}^{n} d_{0j}} \right)^k}{100}pi​=1001+99j​⋅(maxj=1n​d0j​d0i​​)k​。50/100/200/500/1000 节点的路线长度上限为 3/4/5/8/12。（注：原文公式中 jjj 未明确定义，且未给出 kkk 的具体取值）
  • MKP：价值与约束权重均匀采样于 [0,1]，容量在最大单项与总权重之间抽取；训练 m=5。
  • Offline BPP：箱容量 150，物品大小均匀采样于 [20,100]。

以上生成规则来自 Appendix B，非企业实测数据。完整随机种子与数据文件未在当前材料中明确提供。

Prompt 设计与角色边界

Appendix E 提供角色提示模板。输入包含任务说明、候选思想、代码、目标值和反馈；不同角色承接不同修改方向。

  • Explorer：提出具有全局多样性与长期潜力的新算法方向。
  • Exploiter：保留有效部分，寻找短期局部改进。
  • Critic：比较两个实现，分析较好候选的表现并提出具体修改建议。
  • Integrator：合成探索与利用输出，产出仍需执行评分的新候选。

我的评论

最有价值的机制

[分析] 探索与利用分支先产生差异，再由外部执行、比较反思和融合验证。记忆记录目标变化，使建议有机会被效果约束。

最需要补的证据

[分析] 相同 token 与评估预算下的对照；角色提示和温度的独立效应；记忆长度、候选保留、失败重试及原始种子。

替代解释：[分析] 更多采样、更长提示或不同温度也可能贡献增益。单删角色若改变计算量，不能把所有差异归因于角色通信。

作者局限与读者分析分开：当前材料未找到独立局限性清单。作者在结论提出扩展到连续、混合整数和现实物流/调度；这些是未来工作。[§5]

结论边界：一个模型、合成数据、固定求解框架；没有证明工业效果或通用协作定理。评估次数优势不等于费用优势，误差条不等于显著性检验。

One More Thing

值得保存的不是“四个角色一定更强”，而是“每个生成、反思和融合步骤都能回到实际测量”。

[假设] 可尝试按每轮改善与 token 成本自适应停止协作，代替固定三轮。最小验证：同预算比较固定 1/3/5 轮、随机停止和收益阈值停止；在路由与装箱任务上分别测试。如果省成本却失去独立测试质量，则假设失败。创新状态：未核验。[启发来源：Table 3]
