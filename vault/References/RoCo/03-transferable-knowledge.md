# RoCo：可迁移知识与研究想法

## 1. 一句话提炼

[原文事实] RoCo 将不同搜索方向的候选生成、程序执行评分、比较式反思和精英变异连成一条搜索链。[§3；Algorithm 1]

[分析] 最值得复用的是“用真实目标变化约束反思和融合”的机制。仅复制 Explorer、Critic 等角色名，无法保证产生多样性或改善质量。

本笔记直接依据身份匹配的 MinerU 全文、结构数据、导出图像及原始 PDF 核验。它不以全文总结或 HTML 为事实来源。

## 2. 可迁移的方法块

### 2.1 把自然语言、程序和分数放在同一个候选对象中

[原文事实] 启发式对象包含思想说明、Python 函数和适应度；该表示沿用 EoH。[§3.2]

[分析] 在自动算法设计、代码搜索或规则优化中，可为每个候选保留三类字段：意图、可执行实现、测量结果。这样反馈可以针对实现和实际表现，而不是只讨论文字方案。

**适用条件**：候选可在有限时间内执行，有明确目标与可行性检查。**边界**：执行分数不一定代表部署质量；思想描述也可能与代码不一致。最小检查是同时记录函数输入输出、执行失败和评分版本。

### 2.2 让探索与局部改进产生可区分的输出

[原文事实] Explorer 强调全局多样性与长期潜力；Exploiter 强调局部改进。实验设置 temperature 分别为 1.3、0.8。[§3.4；§4.1；Appendix E prompts]

[分析] 两条分支可承接不同的修改范围：一条允许重构启发式思想，一条保持主要结构并修正薄弱处。角色差异需要通过生成候选的结构或行为差异来测量。

**适用条件**：搜索空间同时存在局部可改进性和新方向价值。**边界**：论文同时改变角色提示与温度，没有单独隔离两者的贡献；不能把高温本身等同于有效多样性。

### 2.3 比较两个候选，再生成具体修改建议

[原文事实] Critic 比较候选对，产生反馈与反思；附录提示包含代码、目标值和改善方向。[Eq. 13；Appendix E]

[分析] 成对比较比只看一个候选更容易定位差异。迁移时，给 Critic 同一评估协议下的分数、具体失败实例和代码差异，可检查建议是否与证据一致。

**适用条件**：两个候选可在同一实例集与预算下比较。**边界**：不同随机轨迹的分数差可能被误解为代码机制。论文未证明 Critic 的解释具有因果正确性。最小验证是执行其建议，并检查改善是否复现。

### 2.4 融合需要再次执行评估

[原文事实] Integrator 融合探索与利用分支，末轮后又融合两条分支各自的最佳候选。融合输出进入候选集合，由目标表现选择。[§3.4；Algorithm 1]

[分析] 可借鉴的是“融合产生一个新候选”，而不是“融合自动继承两个父代优点”。把融合候选与直接保留最佳父代比较，才能判断融合的净价值。

**适用条件**：父代具有可组合的模块或规则。**边界**：模块间可能有冲突；接口合法并不保证算法有效。应保留父代分数、融合分数和新增评估成本。

### 2.5 记忆记录“建议—修改—目标变化”

[原文事实] 长期反思使用短期反思、修改前后目标值及差值。正文还保留角色历史记忆，并用记忆指导两个精英个体的多方向变异。[Eqs. 15–18]

[分析] 可把每次修改形成记录：当时问题状态、建议、实际改动、目标变化、执行失败。记忆压缩时优先保留经过重复评估的结果，避免仅记住一次幸运改善。

**适用条件**：多轮或多代搜索需要复用经验。**边界**：论文未提供完整的历史记忆容量、淘汰策略和跨任务有效性验证。状态改变后，过去有效的建议可能失效。

## 3. 可迁移的实验与证据设计

### 3.1 固定求解骨架，比较不同组件生成方法

[原文事实] ACO 下搜索启发式测度，GLS 下搜索惩罚启发式；RoCo 没有重写所有求解步骤。[§4.2；Appendix C]

[分析] 新研究可先固定执行骨架，让不同方法修改同一个组件接口。这样更容易定位性能变化的来源。仍需统一超时、评估次数、种子和失败处理，避免接口相同但执行预算不同。

### 3.2 将结构信息访问作为实验变量

[原文事实] 白盒暴露完整结构，黑盒提供抽象边属性并限制全局结构访问。[Appendix D]

[分析] 可以比较完整结构、局部特征和标量反馈三种信息条件。第三种是研究扩展，原文未验证。应逐项记录提示中可见内容、函数输入、评估反馈和工具权限。

### 3.3 在小规模搜索，在更大规模测试

[原文事实] ACO–TSP 在 5 个 TSP50 上搜索，再在 50、100、200 节点上测试；其他任务也采用规模迁移。[Table 7；Tables 1–2]

[分析] 该设计能检查启发式是否只是记住训练规模。需要独立实例、固定随机种子和明确选模协议。它不等同于跨任务、跨分布或现实场景泛化。

### 3.4 对角色、记忆和轮数分别作消融

[原文事实] Table 3 删除 Explorer、Exploiter、Integrator、Elite Mutation、MAS，并改变协作轮数。[§4.3]

[分析] 可复用消融维度，但删除组件时要写明预算重新分配方式。若删除角色同时减少 API 调用或候选评估，无法将差异完全归因于协作机制。

### 3.5 按证据类型分开写均值、稳定性和成本

[原文事实] 主表为 3 次平均；黑盒 Figure 3 写 4 次独立运行；正文 API 预算与附录评估预算并不一致。[Tables 1–2；Figure 3；§4.1；Appendix D]

[分析] 后续实验至少分别记录：最终目标、跨运行标准差、有效候选数、执行失败数、LLM 请求数、输入/输出 token 和墙钟时间。论文仅有其中一部分，不能从 evaluations 外推全部成本。

## 4. 可迁移的写法和组织方式

[原文事实] 原文按背景缺口、候选表示、系统框架、角色分工、反思机制、主结果、消融展开。[§1–4]

[分析] 可复用的论证顺序是：

1. 说明已有搜索在哪一种条件下不足。
2. 写清输入、输出、可执行表示和评分依据。
3. 用模块图和伪代码说明新增候选如何产生。
4. 用主表回答有效性，用消融回答机制，用跨规模测试回答范围。
5. 把原文事实、解释与未验证扩展分开。

表格中箭头、比较集合、运行次数、预算单位和缺失项必须显式写出。不能让“最优项数量”只靠加粗推断。本篇白盒“10/15”并未被表格支持，是证据审计的反例，而不是可模仿的结论写法。

## 5. 适用场景与不应迁移的内容

**可尝试的场景**：[分析]

- 存在可执行函数接口的启发式搜索。
- 局部修正与新结构探索均有价值的算法设计。
- 能保留客观评估结果的多轮代码改进。

**不应直接照搬**：[分析]

- 不把 GPT-4o-mini 和固定温度当成通用最佳设置。
- 不把三轮视为所有任务的最优轮数；Table 3 只覆盖所报告 TSP 条件。
- 不把黑盒结构访问限制等同于完全未知现实系统。
- 不把合成实例上的比较等同于工业物流、调度或安全关键决策的验证。
- 不把 Figure 2 的 Iterations 横轴当成已核实的 LLM API 调用或墙钟时间。
- 不把较小误差条、标准差重叠或均值小差异直接当成显著性结论。

## 6. 批判性分析（非原文事实）

### 6.1 角色分工与温度变化存在替代解释

[分析] Explorer 的高温可能增加候选差异；更长提示、多次生成或更多候选也可能贡献改进。Table 3 没有报告对提示长度、温度与 token 的完整因子控制。

**为什么重要**：否则无法分辨角色协议与额外采样的价值。**最小验证**：做角色提示 × 温度差异的 2×2 对比，统一调用、评估与 token 上限；报告生成合法率和最终质量。[证据依据：§4.1，Table 3]

### 6.2 预算公平性无法由原文直接判定

[分析] “每代 400 次 API 调用”和“最多 400 次评估”是不同的计数。Critic 的调用不一定产生一个可评估候选。原文没有足够日志判断实际费用高低。

**为什么重要**：方法可能用较少评估取得好结果，但付出更多模型计算。**最小验证**：同时画 quality–evaluations、quality–tokens 和 quality–wall-clock 曲线；不预先认定 RoCo 具有成本劣势或优势。[§4.1；Appendix D]

### 6.3 白盒最优项计数有事实冲突

[原文事实] Table 1 的 EoH BPP700 印为 218.516，RoCo 为 283.734。正文说 RoCo 为 10/15 最优。[Table 1；§4.2]

[分析] 按五种 LLM 方法的打印数值，RoCo 严格最优为 9/15；加入 ACO、DeepACO 后为 7/15。加粗不能覆盖打印数值。不能擅自猜测 EoH 的正确值。

**最小验证**：向作者索取 Table 1 的原始结果和统计脚本；若取得更正，再更新排名。当前不能用“10/15”支撑总体优势。

### 6.4 稳定性结论需要区分主表与图

[分析] Figure 3 的 4-run 均值和标准差不能直接并入 3-run 主表；黑盒 TSP 主表由 ReEvo 领先，而图上的均值排序不同，至少说明统计口径应单独解释。

**最小验证**：在同一测试实例、相同种子集合上重跑各方法，报告全部逐次结果、置信区间和失败率。[Table 2；Figure 3]

### 6.5 消融支持局部经验，不足以证明全部角色必要

[分析] 黑盒移除 Integrator 的均值与波动恶化明显；白盒完整 RoCo 与 EoH 只差 0.001。应同时报告效应大小、配对差和成本，而不是统一写“每个角色不可缺”。标准差是否重叠并非正式检验。

**最小验证**：固定评估/token 预算，在多个任务上运行配对消融，并预先确定统计检验方案。[Table 3]

## 7. 知识连接与可迁移原则

- [原文事实] **EoH** 提供种群、思想/代码表示以及四类进化提示；RoCo 在该骨架上加入协作模块。[§3.2–3.3；Appendix E]
- [原文事实] **ReEvo** 被作者用作反思式进化与实例生成协议的参照。[§1–2；Appendix B–D]
- [原文事实] **LEO** 已有探索与利用池。作者认为 RoCo 的增量是明确角色与通信，不能将探索/利用二分宣称为首次出现。[§1]
- [待核验连接] 与上下文 bandit 的自适应分配可形成组合，但原文没有提出这种分配策略。本轮未独立核验相关方法谱系，不能声称该组合新颖。
- [待核验连接] 与带证据的程序记忆、经验回放相似之处是保留修改及结果；论文未证明与这些机制等价。具体外部方法连接待逐篇核验。
- [用户提供] 当前只给出论文题名及三件套任务，没有提供研究项目、目标问题或已有实验。**对当前项目的匹配程度：当前材料无法评估。**

## 8. 对当前研究的可检验想法

### 8.1 [假设] 根据边际收益自适应停止协作

- **来源**：Table 3 的 1→3 轮改善，4、5 轮无稳定进一步增益。
- **相对原文的增量**：用每轮新增评估收益和 token 成本决定继续、停止或转入变异；原文固定轮数。
- **初始方法**：比较固定 1/3/5 轮、随机停止、简单收益阈值停止；保留最佳已评估候选。
- **最小验证**：在至少一个路由任务和一个装箱任务上，用相同总 token 与评估上限、相同种子组测试最终质量与成本。
- **失败条件**：节省成本却持续丢失较晚出现的高质量候选，或同成本下不优于固定三轮。
- **创新状态**：未核验；需要先查自适应推理和进化搜索预算分配文献。

### 8.2 [假设] 将反思绑定到可追溯失败实例

- **来源**：Eq. 15 将反思与目标变化绑定，但目标均值无法定位在哪些实例改善或恶化。
- **相对原文的增量**：Critic 接收代表性失败实例、配对分数差与可执行性错误，生成可测试修改；记忆保留实例条件。
- **初始方法**：设置“只有聚合分数”和“分数 + 实例证据”的对照，控制提示/token 开销。
- **最小验证**：记录训练实例上改善分布、独立测试质量和错误建议比例；对保留反思作删除/打乱对照。
- **失败条件**：对训练失败实例过拟合；独立测试无增益；打乱证据后效果不变。
- **创新状态**：未核验；当前不能声称为首次证据式反思。

### 8.3 [假设] 按候选行为差异选择融合对象

- **来源**：Appendix E 使用排名邻近的精英对，Integrator 融合探索与利用候选。
- **相对原文的增量**：在高质量候选中优先选“失败实例互补或行为不同”的组合，替代仅按排名邻近的选择。
- **初始方法**：用同一实例集上的决策或目标向量定义候选差异，控制父代质量和新增评估。
- **最小验证**：比较排名邻近、随机精英和行为互补选择；报告融合后相对最佳父代的增益及额外成本。
- **失败条件**：互补性不能预测融合增益，或测量行为差异的开销抵消质量优势。
- **创新状态**：未核验；需检索 diversity、niching 和语义交叉相关工作。

## 9. 可执行清单

1. 定义待搜索的函数接口、可行性检查、统一目标方向和超时规则。
2. 同时保存意图、代码、实例级分数与失败，不把模型解释当评估结果。
3. 先做同预算 EoH 与四角色版本，再做温度、融合、记忆和轮数对照。
4. 分开记录评估次数、LLM 调用、token 和总时间；检验跨规模独立实例。
5. 复现前核实原文 Table 1 异常、预算口径、Figure 3 运行次数和中间候选保留规则。
