#### 任务材料与接口

以下材料来自[主计划所列的非官方仓库固定版本](多智能体协作的通用启发式自动设计.md)，已按本任务接入：

- `problems/<任务>/`：固定求解器、实例及 `eval.py`。

TSP＋ACO 候选的接口为：

```python
def heuristics_v2(distance_matrix: np.ndarray) -> np.ndarray:
    ...
```

输出是与输入同形状的边启发式评分矩阵，由固定 ACO 构造路径。候选只可修改指定函数、内部辅助函数与获准参数；固定调用代码、公共配置、问题约束、目标、求解预算和评价脚本不交由候选修改。

工程训练集使用 5 个 50 节点实例；来源与种子在接入时登记。使用 30 只蚂蚁、200 轮训练迭代和 60 秒整训练集保护时限。蚂蚁数与训练迭代依据 [P1 的 TSP 参数](P1-任务与正式对照接入.md)，但 P1 完成不是 P0 的前置条件；若接入脚本的默认设置不同，在原脚本中局部调整并记录，再冻结本阶段配置。

#### 评价调用与检查

评价直接调用原任务脚本，沿用其实际参数：

```text
python -u <任务目录>/eval.py <实例规模> <候选任务运行根目录> train
```

每个候选使用独立运行目录，避免并行写入同一个 `gpt.py`；每候选启动一次评价脚本，由脚本遍历完整训练集。脚本负责导入候选、运行固定求解框架、检查输出与解的合法性并汇总原始目标。缺少必要检查时只在原任务脚本内局部补齐，不另建通用评分层。

控制程序读取原有结果并计算 Fitness，记录 stdout、stderr、输出文件和资源用量。60 秒时限覆盖整个训练集，不按实例重置；超时后终止进程树，超时或部分输出仅供诊断。零退出码或单个数值不能代替完整性与合法性检查。

用单调时钟记录评价子进程从启动到结束的完整耗时，覆盖加载、预处理、求解、脚本检查和输出。若另报单实例或核心求解耗时，在原任务脚本登记测量点。普通子进程不提供容器级隔离。

**验收：** 各角色只收到[对应提示规定的字段](../../Knowledge/通用启发式自动设计框架.md#34-各角色的读取权限与输出格式)；候选来源、评价和调用顺序可追溯。语法／接口错误、非法输出、评价超时和候选数量不足均按下列约定处理。检查失败时回到任务2或本任务修正，不运行完整一代。

#### 实现顺序与记录

1. 对每个提案登记唯一候选 ID、来源角色／算子、父候选、代次和轮次；检查语法、接口与修改范围，通过后调用任务2的评价入口。代码修改产生新 ID。来源字段仅用于记录，不自动加入模型提示。
2. 按[初始化合同](../../Knowledge/通用启发式自动设计框架.md#37-初始种群建立)生成并评价 30 个原始提案，去重后选出 N=10。无种子提示只提供任务、模块、接口和必要上下文，不提供已有启发式代码。
3. 按[代内协作合同](../../Knowledge/通用启发式自动设计框架.md#38-eoh-外层双精英与代内协作)先执行 EoH 四算子，再从同一本代原种群抽取并固定精英 A/B。Critic 比较后，Q/E 并行从 B 启动；三轮中两支并行续写，各自完成评价后逐轮融合，再从正式轮次有效提案中各选最佳进行末轮融合。
4. 按[反思与筛选合同](../../Knowledge/通用启发式自动设计框架.md#39-本代反思三方向精英变异与筛选)形成 Q/E/I 本代经验，以原始 A/B 生成六个变异；从固定候选池准入、去重并选取 Top N。筛选成功后才追加角色历史。
5. 记录每个调用与评价的输入输出关联、实际开销、失败与跳过原因。记录 Q/E 从 B 到启动候选以及每轮前后的目标变化，供长期反思使用。按同一训练 Fitness 排序，同分按生成顺序；代码去重仅在本运行内执行，保留最早完整有效评价及各次实际开销。

初始化逐次生成前和完整代开始前检查预算；预算不足以完成下一次提案或覆盖完整一代及重试预留时停止。模型提示、响应、可取得的模型／CLI 版本与用量按运行保存；模型名称不代表固定权重快照。

#### 失败路径检查

- 候选语法、接口、越权、运行、数值或解合法性出错时，保留原提案、错误证据和实际开销；无效候选没有正常 Fitness，不触发自动修复调用或额外重评。
- 启动提案无效时沿用 B；正式轮次提案无效时沿用该分支上一有效状态。合法但目标较差的提案仍按正常流程续写。
- 融合输入缺失时记录跳过；两个输入相同仍执行既定融合槽位。融合或变异输出无效时保留失败记录，不补提案。
- 初始化或代末有效不同候选不足 N 时停止，不补入额外提案或旧父代。正式候选池不混入旧父代、启动状态或早轮提案。
- 环境或评价脚本故障单独记录。评价语义不可信时暂停，修正后重新核验受影响结果；不让模型修改评价规则。

评价脚本能否识别非法输出由任务2验收；本任务验证控制流程是否正确记录、回退和停止。
