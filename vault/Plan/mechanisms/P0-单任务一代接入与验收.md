所属主计划：[多智能体协作的通用启发式自动设计](多智能体协作的通用启发式自动设计.md)。阶段总体状态见主计划；本文件维护任务状态。

## 目标与进入条件

打通 ACO＋TSP 白盒任务，从模型生成、初始种群到完整一代筛选和记忆追加，留下可重放的工程验收记录。只使用已登记的工程试运行实例，正式测试数据不进入本阶段。

☑ 已确认 RoCo 主流程、Q/E 目标替换、EoH 无种子初始化、目标值适应度、已有脚本复用、本机执行和订阅模型路线。确认这些设计不等于真实调用、脚本接入或算法运行已经验收。

模型调用和评价接入通过后冻结预算，再实现并检查控制流程，最后执行初始化和完整一代。任何前置任务未通过时，不开始依赖它的运行。

## 已确认合同与待决事项

共享方法、各角色读取权限、候选表示、排序和失败处理，以[方法框架](../../Knowledge/通用启发式自动设计框架.md)为准。非官方任务材料的固定来源与采用边界见[主计划](多智能体协作的通用启发式自动设计.md)。

使用当前订阅的 GPT-5.6 Luna（`gpt-5.6-luna`）和现有 Codex CLI，不使用思考强度参数。任务1核验真实调用方式与可取得的生效信息；无法满足要求时停在该任务。

接口、实例和种子由任务2核验；资源和预算由任务3依据实测冻结。候选技术错误只记录，不自动修复或重评。正式对照和消融属于后续阶段，不作为 P0 开工条件。

## 任务与验收

### ☑ 任务1：模型真实调用

**动作：** 通过已有 Codex CLI 和 ChatGPT 登录调用指定模型，不使用思考强度参数。核验 Thought 与完整函数代码的生成、论文给出的 Critic 反思标签、代码输出的解析约定、长期反思合并约定，以及实际会话上下文和截断方式。

**交付物：** 可重复的本机调用方式、提示与响应原文、解析约定、可取得的模型／CLI 版本、用量与错误记录。实际调用记录保存到 `outputs/`。

**验收：** 成功解析一个符合 TSP 模块签名的提案；Critic 与长期反思输出可按[角色合同](../../Knowledge/通用启发式自动设计框架.md#34-各角色的读取权限与输出格式)读取。认证、额度、调用要求或输出协议不满足时停在本任务，不自动换模型或付费 API。

#### 2026-11-03 实测与复现

- 从项目根目录执行 `python -B scripts/p0_model_probe.py`，每次在 `outputs/p0_model_call/` 下创建新的运行目录。脚本使用现有 ChatGPT 登录与 `codex exec`，显式请求 `gpt-5.6-luna`，未传思考强度参数，也未改用户级配置。
- [本次提示、响应、原始事件、错误与用量](../../../outputs/p0_model_call/20261103_154718_4198a9aa/calls.jsonl)保留五次真实调用：无种子提案、初始 Critic、Q/E 本代长期反思和 Integrator 合并。Critic 代码和目标值、Q/E 目标变化均为协议测试用的模拟数据，不是评价结果。
- 本机 CLI 为 `codex-cli 0.163.0`。本机模型目录列出 `gpt-5.6-luna`；调用事件没有返回独立的模型权重快照版本。五次响应共报告输入 111,229 tokens，其中缓存输入 52,480 tokens，输出 682 tokens；不据此推算订阅费用。
- 代码输出使用项目约定：依次输出非空 `<thought>...</thought>` 与 `<code>...</code>`，不附 Markdown 围栏或额外文字。解析器检查 Python 语法、完整模块所需的 `import numpy as np` 和 `heuristics_v2(distance_matrix: np.ndarray) -> np.ndarray` 签名，不执行候选。该标签格式是接入约定，不是论文公开的统一输出模板。
- 初始 Critic 的 `<ref>`、`<ans>` 与 Q/E 长期反思的 `<ans>` 均通过标签和词数检查。Integrator 合并仅接收两份长期反思，输出非空纯文本；论文没有给出独立的合并输出模板。
- 每次调用均使用新的 `--ephemeral` 会话，不恢复其他会话；脚本不截断显式提示。五次 JSONL 均无可见的上下文压缩事件。原始事件不提供服务端完整输入，因此不能据此证明内部没有截断，也未测试长历史的压缩行为。后续控制流程须在使用长历史前继续核验上下文预算与截断。
- 同目录的 `codex debug prompt-input` 对照包含完整显式提示，并显示额外指令、skills 和环境内容；此调试命令会加载用户配置，不能接受实际调用使用的 `--ignore-user-config`，因此只能作为对照，不能当作本次调用的完整上下文。模型目录中的 `truncation_policy` 字段也不能直接解释为用户提示的截断阈值。[OpenAI 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)说明 CLI 的指令发现和长度限制。
- 五次请求均先发生 WebSocket 超时重试，随后由 CLI 自动转 HTTPS 并成功，每次约 120 秒。首次脚本误把已恢复的重试事件判为失败；修正解析器后复用原始提案，未重新生成。该失败、恢复及全部原始事件均保留。脚本不自动重试格式错误或修复候选代码。
- `python -B -m unittest discover -s tests -v` 的六项检查通过；另对原始记录独立核对了函数签名和合并输入，并用当前解析器重新读取五份响应。候选未执行，数值、解合法性和评价结果留待任务2。

**动作：** 接入固定来源版本的 TSP-ACO 任务材料，保留真实函数签名和原脚本的导入关系。用同一评价入口检查参考函数与模型候选；参考函数只用于工程接入，不进入初始化提示或种群。

**交付物：** 可调用的任务材料与评价入口，以及来源版本、接入修改、实际实例、随机种子、逐实例输出和资源记录。实际运行记录保存到 `outputs/`。

**验收：** 核对逐实例目标及平均值、目标方向、完整迭代、接口／数值／解合法性和超时判定。参考结果不能重放或非法输出未被拒绝时，修正并重新核验本任务，不进入完整一代运行。

#### 任务材料与接口

以下路径参照[主计划所列的非官方仓库固定版本](多智能体协作的通用启发式自动设计.md)。本项目尚未完成接入，实际内容和目录结构由本任务核验：

- `cfg/problem/<任务>.yaml`：任务名称、规模、原始目标方向和说明。
- `prompts/<任务>/func_desc.txt`、`func_signature.txt`：模块职责与函数签名。
- `problems/<任务>/`：固定求解器、实例及 `eval.py`。

TSP＋ACO 候选的接口为：

```python
def heuristics_v2(distance_matrix: np.ndarray) -> np.ndarray:
    ...
```

输出是与输入同形状的边启发式评分矩阵，由固定 ACO 构造路径。候选只可修改指定函数、内部辅助函数与获准参数；固定调用代码、公共配置、问题约束、目标、求解预算和评价脚本不交由候选修改。

工程训练集使用 5 个 50 节点实例；来源与种子在接入时登记。使用 30 只蚂蚁、200 轮训练迭代和 60 秒整训练集保护时限。蚂蚁数与训练迭代依据 [P1 的 TSP 参数](P1-任务与正式对照接入.md)，但 P1 完成不是 P0 的前置条件；若接入脚本的默认设置不同，在原脚本中局部调整并记录，再冻结本阶段配置。

#### 评价调用与检查

评价直接调用原任务脚本，沿用其实际参数：

```text
python -u <任务目录>/eval.py <实例规模> <候选任务运行根目录> train
```

每个候选使用独立运行目录，避免并行写入同一个 `gpt.py`；每候选启动一次评价脚本，由脚本遍历完整训练集。脚本负责导入候选、运行固定求解框架、检查输出与解的合法性并汇总原始目标。缺少必要检查时只在原任务脚本内局部补齐，不另建通用评分层。

控制程序读取原有结果并计算 Fitness，记录 stdout、stderr、输出文件和资源用量。60 秒时限覆盖整个训练集，不按实例重置；超时后终止进程树，超时或部分输出仅供诊断。零退出码或单个数值不能代替完整性与合法性检查。

用单调时钟记录评价子进程从启动到结束的完整耗时，覆盖加载、预处理、求解、脚本检查和输出。若另报单实例或核心求解耗时，在原任务脚本登记测量点。普通子进程不提供容器级隔离。

### ☐ 任务3：配置与预算冻结

**动作：** 依据任务1–2的实测结果、订阅额度和本机可用资源，冻结当前运行配置与预算，覆盖正常路径及基础设施重试预留。运行前检查资源占用、输出位置和交互影响。

**交付物：** 本次运行的冻结配置、预算及其估算依据。配置与代码按实际接入目录登记；运行与预算记录保存到 `outputs/`。

**验收：** 确认任务、白盒提示条件、模型、训练实例及其来源、种子、并发、CPU、内存、NumPy／BLAS 线程数、模型调用上限和评价 CPU 时间上限均有记录。待定项不能作为可执行默认值；预算不足时不启动完整一代。进程保持 Normal 优先级。

#### 预算计数

N=10、正式协作三轮时，一代正常路径的结构计数如下。每个代码生成槽位对应一次请求模型生成一份候选代码的调用；只生成反思或建议的调用不计入该列。

| 操作 | 模型调用 | 代码生成槽位 |
| --- | --- | --- |
| EoH 四算子 | 40 | 40 |
| 初始 Critic 与双分支启动 | 3 | 2 |
| 三轮 Critic、Q/E、融合 | 12 | 9 |
| 末轮精英融合 | 1 | 1 |
| Q/E 长期反思与 I 合并 | 3 | 0 |
| 六个精英变异 | 6 | 6 |
| 合计 | 65 | 58 |

初始化另有 30 次代码生成。因此初始化加完整一代的正常路径为 **95 次模型调用、88 个代码生成槽位**。代码生成可能失败或产生重复；实际获得的代码、有效候选和去重后数量不保证达到槽位数。

上述是正常路径的结构计数，不是已冻结的资源上限。跳过的调用按实际记录；探针、错误用例、基础设施重试和最终检查均另计实际开销，并纳入预算。并行步骤须共同检查可用额度。

求解预算执行任务2的固定参数；研发预算分别登记模型用量和本机计算消耗。订阅缺失的 token 字段标为缺失，不以 API 单价推算订阅扣费。正式实验重复数与总预算在 P1 确定。

### ☐ 任务4：控制流程与错误处理

**动作：** 按[方法框架](../../Knowledge/通用启发式自动设计框架.md)实现候选登记、模型调用、任务评价、种群筛选、反思与预算检查。先用针对当前实现的最小用例核验正常与失败路径，再执行任务5的完整运行。

**交付物：** 控制流程代码、可复现检查命令和对应验收记录。代码位置按实际接入目录登记；检查记录保存到 `outputs/`。

**验收：** 各角色只收到[对应提示规定的字段](../../Knowledge/通用启发式自动设计框架.md#34-各角色的读取权限与输出格式)；候选来源、评价和调用顺序可追溯。语法／接口错误、非法输出、评价超时和候选数量不足均按下列约定处理。检查失败时回到任务2或本任务修正，不运行完整一代。

#### 实现顺序与记录

1. 对每个提案登记唯一候选 ID、来源角色／算子、父候选、代次和轮次；检查语法、接口与修改范围，通过后调用任务2的评价入口。代码修改产生新 ID。来源字段仅用于记录，不自动加入模型提示。
2. 按[初始化合同](../../Knowledge/通用启发式自动设计框架.md#37-初始种群建立)生成并评价 30 个原始提案，去重后选出 N=10。无种子提示只提供任务、模块、接口和必要上下文，不提供已有启发式代码。
3. 按[代内协作合同](../../Knowledge/通用启发式自动设计框架.md#38-eoh-外层双精英与代内协作)先执行 EoH 四算子，再从同一本代原种群抽取并固定精英 A/B。Critic 比较后，Q/E 并行从 B 启动；三轮中两支并行续写，各自完成评价后逐轮融合，再从正式轮次有效提案中各选最佳进行末轮融合。
4. 按[反思与筛选合同](../../Knowledge/通用启发式自动设计框架.md#39-本代反思三方向精英变异与筛选)形成 Q/E/I 本代经验，以原始 A/B 生成六个变异；从固定候选池准入、去重并选取 Top N。筛选成功后才追加角色历史。
5. 记录每个调用与评价的输入输出关联、实际开销、失败与跳过原因。记录 Q/E 从 B 到启动候选以及每轮前后的目标变化，供长期反思使用。按同一训练 Fitness 排序，同分按生成顺序；代码去重仅在本运行内执行，保留最早完整有效评价及各次实际开销。

初始化逐次生成前和完整代开始前检查预算；预算不足以完成下一次提案或覆盖完整一代及重试预留时停止。模型提示、响应、可取得的模型／CLI 版本与用量按运行保存；模型名称不代表固定权重快照。

#### 失败路径检查

- 候选语法、接口、越权、运行、数值或解合法性出错时，保留原提案、错误证据和实际开销；无效候选没有正常 Fitness，不触发自动修复调用或额外重评。
- 启动提案无效时沿用 B；正式轮次提案无效时沿用该分支上一有效状态。合法但目标较差的提案仍按正常流程续写。
- 融合输入缺失时记录跳过；两个输入相同仍执行既定融合槽位。融合或变异输出无效时保留失败记录，不补提案。
- 初始化或代末有效不同候选不足 N 时停止，不补入额外提案或旧父代。正式候选池不混入旧父代、启动状态或早轮提案。
- 环境或评价脚本故障单独记录。评价语义不可信时暂停，修正后重新核验受影响结果；不让模型修改评价规则。

评价脚本能否识别非法输出由任务2验收；本任务验证控制流程是否正确记录、回退和停止。

### ☐ 任务5：初始化、完整一代与记录重放

**动作：** 在任务1–4通过且配置和预算冻结后，执行一次初始化与完整一代。重放来源、候选、评价、各槽位及代内时序记录，核对种群与角色经验。

**交付物：** 全部生成、评价、失败和资源记录；原始精英 A/B；每个槽位的输入输出关联；最终种群；按角色保存的本代经验；可复现的验收命令。实际运行记录与 stdout 保存到 `outputs/`。

**验收：** 完成 30 个初始化提案与一代既定流程；正常路径的调用与代码生成槽位计数符合任务3，实际跳过、失败与基础设施重试逐项说明。确认原始 A/B 在代内不变，三轮、融合、反思、六变异、Top N 和历史追加顺序完整。任何中途终止、预算不足或有效不同候选不足 N 均记为未完成，不删步骤或补旧父代凑成一代。

## 完成条件与停止处理

任务1–5均通过对应验收，配置已冻结，完整一代与失败处理均有可重放记录，才算 P0 完成并进入 P1。通过只支持工程接入正确性，不形成算法性能结论。

认证、额度、接口或评价语义不可信时停在对应任务；候选数量不足、预算不足或中途终止时记录未完成。原始输出和验收记录按实际运行保存到 `outputs/`。
